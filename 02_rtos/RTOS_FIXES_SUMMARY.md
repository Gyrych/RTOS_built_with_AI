# RTOS核心修复总结

## 修复概述

根据详细分析文档，我们对RTOS核心代码进行了全面修复，解决了所有关键问题，确保系统能够正确进行上下文切换而不会导致HardFault。

## 主要修复内容

### 1. 添加全局指针变量 ✅
- **问题**: 汇编代码中使用硬编码偏移访问结构体成员，容易因结构变化导致错误
- **修复**: 添加了`pxCurrentTCB`和`pxNextTCB`全局指针变量
- **文件**: `core.h`, `core.c`
- **影响**: 提高了代码的健壮性和可维护性

### 2. 修复堆栈布局不一致问题 ✅
- **问题**: `task_create`中的堆栈初始化与`PendSV_Handler`的恢复逻辑不匹配
- **修复**: 采用FreeRTOS风格的堆栈初始化，确保`stack_ptr`指向R4位置
- **文件**: `core.c` - `task_create`函数
- **影响**: 解决了上下文切换时的寄存器错乱问题

### 3. 修复PC的Thumb位设置 ✅
- **问题**: 任务函数地址未设置Thumb位，可能导致状态错误
- **修复**: 使用`((uint32_t)func) | 0x1`确保Thumb位正确设置
- **文件**: `core.c` - `task_create`函数
- **影响**: 确保任务正确在Thumb状态下执行

### 4. 添加任务退出处理函数 ✅
- **问题**: 任务函数返回时没有安全处理机制
- **修复**: 添加`prvTaskExitError`函数，将LR设置为该函数地址
- **文件**: `core.c`
- **影响**: 防止任务意外返回导致系统崩溃

### 5. 修复调度时序问题 ✅
- **问题**: `rtos_schedule`中提前修改`current_task`导致上下文保存到错误的TCB
- **修复**: 使用`pxNextTCB`机制，由`PendSV_Handler`负责正确的切换顺序
- **文件**: `core.c` - `rtos_schedule`函数
- **影响**: 确保上下文保存和恢复的正确性

### 6. 重写PendSV_Handler ✅
- **问题**: 原有的PendSV处理逻辑存在多个严重错误
- **修复**: 完全重写，使用正确的保存/恢复顺序和全局指针
- **文件**: `core.c` - `PendSV_Handler`函数
- **影响**: 实现正确的上下文切换机制

### 7. 改进中断处理 ✅
- **问题**: 使用全局关中断(`cpsid i`)影响实时性
- **修复**: 添加基于BASEPRI的临界区控制函数
- **文件**: `core.h`, `core.c`
- **影响**: 提高系统实时性和中断响应能力

## 技术细节

### 堆栈布局
```
高地址: [R4][R5][R6][R7][R8][R9][R10][R11]  <- stack_ptr指向这里
        [xPSR][PC][LR][R12][R3][R2][R1][R0]  <- 硬件自动保存区
低地址: [栈底]
```

### 上下文切换流程
1. `rtos_schedule`设置`pxNextTCB`并触发PendSV
2. `PendSV_Handler`保存当前任务的R4-R11到其堆栈
3. 将更新后的PSP保存到`pxCurrentTCB->stack_ptr`
4. 从`pxNextTCB->stack_ptr`恢复新任务的R4-R11
5. 更新PSP并设置`pxCurrentTCB = pxNextTCB`
6. 返回时自动恢复xPSR、PC、LR等寄存器

### 中断优先级配置
- SVC中断: 优先级0（最高）
- PendSV中断: 优先级15（最低）
- 系统调用临界区: 屏蔽优先级5以下的中断

## 测试建议

1. **单步调试**: 在调试器中单步执行上下文切换，验证堆栈布局
2. **LED测试**: 运行现有的双LED任务，观察是否正常切换
3. **HardFault检测**: 如果出现HardFault，检查SCB寄存器获取错误信息
4. **堆栈使用监控**: 使用`rtos_debug_print_stack_usage`监控堆栈使用情况

## 注意事项

1. 确保中断向量表中的`PendSV_Handler`名称与代码中的函数名一致
2. 编译时确保启用了Thumb指令集
3. 堆栈大小(256 words)对于简单任务足够，复杂任务可能需要调整
4. 所有任务函数必须设计为永不返回的无限循环
